DIAGRAMA 3: FLUXO DE ENVIO DE CONVITES (SEQUÊNCIA)
================================================================================

Admin → Django → Database → SendGrid → Usuário

1. Admin cria/envia convites
   │
   ▼
2. Django busca Survey & Respondents no Database
   │
   ▼
3. Django cria SurveyInvitation no Database
   │
   ▼
4. Django gera Token Único
   │
   ▼
5. Django renderiza Template HTML do email
   │
   ▼
6. Django envia email via SendGrid API
   │
   ▼
7. SendGrid entrega email ao Usuário
   │
   ▼
8. Usuário clica no link do email
   │
   ▼
9. Django valida Token no Database
   │
   ▼
10. Django mostra Formulário de Pesquisa
    │
    ▼
11. Usuário envia Resposta
    │
    ▼
12. Django salva SurveyResponse no Database
    │
    ▼
13. Django mostra Página de Agradecimento

================================================================================
CONFIGURAÇÃO DE REDE
================================================================================

AZURE DNS CONFIGURATION:
─────────────────────────────────────────────────────────
Registro A:
    seudominio.com → IP do App Service

Registro CNAME:
    www.seudominio.com → seudominio.azurewebsites.net

Registro MX (se usar HostGator):
    seudominio.com → mail.hostgator.com (prioridade 10)

Registro TXT (SPF):
    seudominio.com → "v=spf1 include:sendgrid.net ~all"

Registro TXT (DKIM):
    seudominio.com → (chave DKIM do SendGrid)


FIREWALL RULES:
─────────────────────────────────────────────────────────
Azure Database:
    - Permitir: IP do App Service
    - Bloquear: Todo o resto

App Service:
    - Permitir: Internet (HTTPS)
    - Bloquear: Acesso direto (apenas via DNS)

================================================================================
ESCALABILIDADE
================================================================================

ESCALA VERTICAL (Aumentar recursos):
─────────────────────────────────────────────────────────
App Service:
    B1 → B2 → B3 → S1 → S2 → S3
    (Mais CPU e RAM)

Database:
    Basic → General Purpose → Memory Optimized
    (Mais performance)


ESCALA HORIZONTAL (Múltiplas instâncias):
─────────────────────────────────────────────────────────
App Service:
    1 instância → 2 → 3 → N instâncias
    (Load Balancer automático)

Database:
    1 servidor → + Read Replicas
    (Distribuir leitura)
